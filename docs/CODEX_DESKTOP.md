# Настольный Codex: подключение ключа MOX

Дата проверки: 9 сентября 2026 года.

Дополнение 10 сентября: окружение теперь моделирует несколько подписок и стабильные ключи сотрудников. Проверка окна Codex ниже относилась к одному синтетическому серверу; она не доказывает вход в несколько настоящих Pro-подписок или перенос состояния между аккаунтами. См. [модель нескольких подписок](MULTI_SUBSCRIPTIONS.md).

## Установленная версия

- Настольное приложение: 26.903.61454, build 8378.
- Идентификатор приложения: com.openai.codex.
- Встроенный движок: codex-cli 0.153.4.

## Документированная возможность

Настольное приложение использует общие настройки Codex, включая расширенную конфигурацию в config.toml:

- [Agent configuration в настольном приложении](https://learn.chatgpt.com/docs/developer-settings#agent-configuration).
- [Собственные провайдеры: адрес, протокол и авторизация](https://learn.chatgpt.com/docs/config-file/config-advanced#custom-model-providers).
- [Способы авторизации собственного провайдера](https://learn.chatgpt.com/docs/auth#alternative-model-providers).

Сотруднику необходимы **личный ключ MOX и адрес шлюза MOX**. Сам по себе ключ, вставленный в обычную форму OpenAI API key, не меняет адрес сервера и не создаёт право на Pro.

Провайдер настраивается в пользовательском ~/.codex/config.toml. Настройки провайдера в конфигурации отдельного проекта игнорируются — см. [справочник конфигурации](https://learn.chatgpt.com/docs/config-file/config-reference).

Основные настройки проверенного провайдера:

    model_provider = "mox"
    [model_providers.mox]
    name = "MOX"
    base_url = "https://gateway.example.com/v1"
    env_key = "MOX_ACCESS_KEY"
    wire_api = "responses"
    requires_openai_auth = false

Адрес выше — пример. Он не является работающим шлюзом. Персональный ключ должен быть доступен процессу Codex через MOX_ACCESS_KEY. На macOS export в отдельном терминале сам по себе не гарантирует, что приложение из Dock получит переменную; нужен отдельный способ установки ключа или запуска приложения.

## Проверка встроенного движка

Встроенный app-server был запущен с отдельной временной конфигурацией и вымышленным ключом. Сервер принимал запросы только на 127.0.0.1 и возвращал заранее заданный поток Responses SSE.

| Проверка | Результат |
| --- | --- |
| Собственный model_provider и base_url | Приняты движком |
| Authorization: Bearer | Получен именно выданный проверочный ключ |
| Запрос к шлюзу | POST /v1/responses, stream: true |
| Потоковый ответ шлюза | Принят, ход завершён со статусом completed |
| Повторный запрос после отзыва | Сервер вернул 401, ход завершён со статусом failed |
| Авторизация OpenAI и платный вызов модели | Не использовались |

Воспроизводимый сценарий: [scripts/probe-codex-provider.mjs](../scripts/probe-codex-provider.mjs).

## Проверка окна настольного приложения

Запущен отдельный экземпляр установленного приложения. Использовались собственные временные CODEX_HOME и CODEX_ELECTRON_USER_DATA_PATH, а также CODEX_APP_SERVER_FORCE_CLI=1. Существующий профиль и авторизация пользователя не копировались.

В интерфейсе приложения:

1. Пройден стартовый экран; импорт чужих проектов и чатов пропущен.
2. Без входа в ChatGPT появился провайдер MOX local protocol probe.
3. Создан пустой тестовый проект.
4. Отправлена короткая проверочная фраза из обычного поля ввода Codex.
5. Сервер получил пользовательский ключ в запросе к /v1/responses.
6. В чате появился заданный сервером ответ: “MOX local gateway accepted this key.”
7. Ключ отозван на тестовом сервере.
8. Следующее сообщение в том же чате завершилось видимой ошибкой 401 Unauthorized: MOX probe key revoked.

Основной запрос использовал выбранную модель gpt-5.4; приложение также отправило служебный запрос с gpt-5.6-luna. Поэтому настоящий шлюз должен учитывать служебные запросы приложения, а не только выбранную пользователем модель.

Ни один ответ не был сгенерирован моделью OpenAI. Это проверка клиентского протокола, отображения ответа и отзыва доступа.

## Что ещё не подтверждено

- Работа шлюза с реальной подпиской Pro.
- Сохранение всех возможностей подписочного режима при собственном провайдере.
- Разделение прав, квот и данных десяти сотрудников на настоящем сервере.
- Удобная установка личного ключа и настроек на компьютере сотрудника.

## Следующая часть реализации

Движок Codex остаётся на компьютере сотрудника. Сервер MOX должен проверять его ключ и обслуживать совместимый протокол Responses. Панель администратора выдаёт и отзывает ключи в серверном хранилище.

Обработчик /turn из MOX-ADV возвращает прикладной результат рекламного пайплайна. Он не реализует протокол Responses и не может без адаптации использоваться как адрес модельного провайдера настольного Codex.

Официальный вход через OpenAI API key использует API-биллинг. Подписочная авторизация — отдельный способ входа: [Authentication](https://learn.chatgpt.com/docs/auth). Связь собственного шлюза с личной Pro нельзя считать готовой или официально поддержанной на основании настройки base_url.

Документированная альтернатива для удалённого исполнения — подключение настольного приложения к SSH-хосту с установленным и авторизованным Codex: [Remote connections](https://learn.chatgpt.com/docs/remote-connections#connect-to-an-ssh-host). При таком варианте файлы, команды и окружение находятся на удалённом хосте; эту альтернативу здесь не проверяли.
