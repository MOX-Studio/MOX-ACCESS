# MOX ACCESS

Интерактивный прототип панели администратора: сотрудники, выдача и отзыв персональных ключей MOX для доступа через корпоративный шлюз.

Рабочим приложением сотрудника остаётся **настольный Codex**. Панель MOX управляет доступом.

## Открыть

[Прототип в браузере](https://mox-studio.github.io/MOX-ACCESS/)

Локально, с Node.js 20 или новее:

    npm run dev

Откройте адрес из терминала. Зависимости устанавливать не нужно. Весь интерфейс находится в dist/index.html.

## Что можно попробовать

- Начать с десяти демонстрационных сотрудников и уже подключённой в макете Pro за $200.
- Добавить сотрудника с проверкой имени, почты и дубликатов.
- Выдать один активный ключ на сотрудника, увидеть его один раз и скопировать.
- Отозвать ключ и убедиться, что он больше не проходит локальную проверку.
- Выдать новый ключ; старый останется отозванным.
- Найти сотрудника, отфильтровать доступы и посмотреть историю действий.
- Посмотреть способ подключения настольного Codex и результаты проверки.
- Сбросить демо в исходное состояние.

Все сотрудники вымышлены. Адреса используют зарезервированный домен example.com.

## Границы прототипа

Это браузерный прототип без сервера авторизации. Подключение OpenAI показано для демонстрации. Ключи с префиксом mox_demo_ работают только в проверке на этой странице. Они не являются ключами OpenAI и не дают доступа к платной подписке.

Состояние находится в памяти вкладки и сбрасывается после обновления страницы. Полные ключи не сохраняются в журнале, localStorage или файлах. В модели хранятся SHA-256, последние четыре символа, владелец и статус ключа. Проверка внутри браузера иллюстрирует поведение; она не является границей безопасности настоящего сервиса.

GitHub Pages публикует только интерфейс. Реальный шлюз, серверная база ключей, авторизация администратора и подключение к провайдеру в него не входят.

## Совместимость с настольным Codex

Проверен путь **настольный Codex сотрудника → личный ключ → собственный сервер MOX**.

В отдельном экземпляре установленного приложения удалось открыть чат через собственного провайдера, получить заранее заданный ответ локального сервера и увидеть отказ 401 после отзыва ключа. Настоящая подписка или OpenAI API для проверки не использовались.

Сотруднику нужны ключ и адрес шлюза. В стандартном поле OpenAI API key один пользовательский ключ не настраивает адрес сервера.

Результаты проверки: [docs/CODEX_DESKTOP.md](docs/CODEX_DESKTOP.md).

Повторить проверку протокола без OpenAI и платного запроса:

    npm run probe:codex

Или передать путь к движку из настольного приложения:

    npm run probe:codex -- /Applications/ChatGPT.app/Contents/Resources/codex

Скрипт поднимает временный сервер на 127.0.0.1, создаёт отдельную конфигурацию, передаёт вымышленный ключ и проверяет отказ после его отзыва. Сервер возвращает заранее заданный ответ. Существующая авторизация пользователя не читается.

## Проверка интерфейса

Прототип рассчитан на desktop 1920×1080. Проверены выдача, копирование, отзыв, повторная выдача, старый и неизвестный ключи, добавление сотрудника, дубликаты почты, поиск, журнал и сброс. Основной экран с десятью сотрудниками помещается целиком.

Другие размеры экрана, реальное подключение Pro и работа десяти сотрудников через шлюз одновременно не проверены.
