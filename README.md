# MOX ACCESS

Интерактивный прототип панели администратора: несколько подписок в одном окружении, сотрудники, выдача и отзыв персональных ключей MOX.

Рабочим приложением сотрудника остаётся **настольный Codex**. Панель MOX управляет доступом.

## Открыть

[Прототип в браузере](https://mox-studio.github.io/MOX-ACCESS/)

Локально, с Node.js 20 или новее:

    npm run dev

Откройте адрес из терминала. Зависимости устанавливать не нужно. Интерфейс находится в dist/, расчёт периодов и расхода — в dist/usage.js.

## Что можно попробовать

- Начать с десяти демонстрационных сотрудников и двух подключённых в макете подписок Pro.
- Подключать третью и последующие подписки через отдельное окно демо-входа; проверять отмену, дубликаты и повторный вход.
- Приостанавливать или отключать отдельную подписку, сохраняя ключи сотрудников.
- Пользоваться всеми текущими и будущими подписками окружения с одним ключом сотрудника.
- Сравнивать входные и выходные токены каждого сотрудника с Fast и без него за день, неделю и месяц.
- Видеть отдельно неподтверждённый режим и неполные счётчики токенов.
- Добавить сотрудника с проверкой имени, почты и дубликатов.
- Выдать один активный ключ на сотрудника, увидеть его один раз и скопировать.
- Отозвать ключ и убедиться, что он больше не проходит локальную проверку.
- Выдать новый ключ; старый останется отозванным.
- Найти сотрудника, отфильтровать доступы и посмотреть историю действий.
- Посмотреть способ подключения настольного Codex и результаты проверки.
- Проверить выбор подписки для нового чата и сохранение подключения у начатого чата.
- Сбросить демо в исходное состояние.

Все сотрудники вымышлены. Адреса используют зарезервированный домен example.com.

## Границы прототипа

Это браузерный прототип без сервера авторизации. Подключения OpenAI и вход в аккаунты показаны для демонстрации. Ключи с префиксом mox_demo_ работают только в проверке на этой странице. Они не являются ключами OpenAI и не дают доступа к платным подпискам.

Состояние находится в памяти вкладки и сбрасывается после обновления страницы. Полные ключи не сохраняются в журнале, localStorage или файлах. В модели хранятся SHA-256, последние четыре символа, владелец и статус ключа. Проверка внутри браузера иллюстрирует поведение; она не является границей безопасности настоящего сервиса.

GitHub Pages публикует только интерфейс. Реальный шлюз, серверная база ключей, авторизация администратора и подключение к провайдеру в него не входят.

## Несколько подписок

Ключ принадлежит сотруднику в окружении MOX и сохраняется при добавлении или повторной авторизации подписки. Каждый активный ключ автоматически открывает доступ ко всем текущим и будущим подпискам окружения. Настроек подписок для отдельных сотрудников нет.

Новые чаты по очереди выбирают готовые подписки окружения. Каждый начатый чат закреплён за своим подключением. Отзыв ключа, потеря авторизации, пауза или исчерпание лимита останавливают дальнейшие запросы такого чата. Сам ключ может при этом оставаться действующим.

Разбор будущей серверной части и ограничений: [docs/MULTI_SUBSCRIPTIONS.md](docs/MULTI_SUBSCRIPTIONS.md).

## Вход и расход токенов

Вместо ручного ввода имени аккаунта используется кнопка «Войти через OpenAI», отдельное окно и ожидание результата. Сейчас окно содержит только вымышленные аккаунты. Настоящий вход будет выполняться через официальный сценарий OpenAI с подтверждением на сервере MOX.

Расход показан по каждому сотруднику и суммарно по окружению, отдельно для Fast, обычного и неподтверждённого режима. В каждой группе есть входные и выходные токены. Режим фиксируется для каждого запроса по подтверждённому результату, поэтому переключение Fast не меняет историю. День начинается в 00:00 Москвы, неделя — в понедельник, месяц — первого числа. Данные демонстрационные: успешная проверка запроса добавляет 2048 входных и 384 выходных токена. В «Проверке ключа» можно переключить Fast для следующего запроса, а в «Сценариях учёта токенов» — смоделировать подтверждение обычного режима вместо Fast или отсутствие подтверждения. Отзыв ключа сохраняет историю. Отсутствующий счётчик отмечается как неизвестный и не превращается в ноль.

План перехода к настоящему входу и учёту: [docs/AUTH_AND_USAGE.md](docs/AUTH_AND_USAGE.md).

## Совместимость с настольным Codex

Проверен путь **настольный Codex сотрудника → личный ключ → собственный сервер MOX**.

В отдельном экземпляре установленного приложения удалось открыть чат через собственного провайдера, получить заранее заданный ответ локального сервера и увидеть отказ 401 после отзыва ключа. Настоящая подписка или OpenAI API для проверки не использовались.

Сотруднику нужны ключ и адрес шлюза. В стандартном поле OpenAI API key один пользовательский ключ не настраивает адрес сервера.

Результаты проверки: [docs/CODEX_DESKTOP.md](docs/CODEX_DESKTOP.md).

Повторить проверку протокола без OpenAI и платного запроса:

    npm run probe:codex

Или передать путь к движку из настольного приложения:

    npm run probe:codex -- /Applications/ChatGPT.app/Contents/Resources/codex

Скрипт поднимает временный сервер на 127.0.0.1, создаёт отдельную конфигурацию, передаёт вымышленный ключ и проверяет отказ после его отзыва. Сервер возвращает заранее заданный ответ. Существующая авторизация пользователя не читается.

## Проверка интерфейса

Прототип проверен через Playwright в отдельном браузере при 1920×1080. Проверены вход через окно, отмена и блокировка окна, дубликат аккаунта, несовпадение аккаунта при повторном входе, сохранение лимита, автоматический доступ существующего ключа к третьей подписке, расход по сотруднику и периодам, сохранение истории после отзыва и сброс демо. Проверены границы московских суток, недели и месяца, устранение повторных событий и неизвестные счётчики. Для Fast проверены переключение внутри одного чата, возврат провайдера к обычному режиму, отсутствие подтверждения, суммы по всем трём группам и сохранение истории. Основной экран и таблица расхода с десятью сотрудниками помещаются целиком.

Другие размеры экрана, реальная авторизация в двух и более Pro-подписках и работа десяти сотрудников через шлюз одновременно не проверены.
